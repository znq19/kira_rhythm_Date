# 生活节律·日程插件（KRD）

**KiraRhythmDate** 让 KiraAI 中的每个人格拥有独立的生活线：规划、感知当下、触发小项、保留梦与体验，并主动修改后续安排。它不是提醒命令合集，也不要求 bot 为每个小项额外报告一次“完成”。

- 插件 ID：`kira_rhythm_Date`
- 内部名：`KiraRhythmDate`
- 简称：`KRD`
- 核心版本：`KiraAI >=3.1.2`
- 许可证：AGPL-3.0
- 作者：`znq19`
- 图标：`assets/icon.svg`

## 功能总览

### 自主生活闭环

- 每日定时规划，默认 23:00；**已有计划也触发**，作为一次修订机会。
- 当前全部小项终态后，再给予一次规划机会。
- `rhythm_plan` 创建/修订单日或多日计划；多日使用原子事务。
- `rhythm_update` 调整小项、DayState，或保存梦与体验。
- `rhythm_view` 按需读取历史、当前组、diff、配额、目标/约定与体验。
- 目标与约定（Threads）：`goal / promise / project / habit / open_loop / mystery`，带档案、下一步、可选截止、优先级和打卡流水；bot 可在规划/聊天/执行中自行新建、修改、打卡、完成或放弃。
- 空目标层策略 `threads.empty_mode`：`allow` 允许为空、`nudge` 规划时提示 bot 尝试建立真实目标（默认，不阻断）、`require` 规划时要求活动目标达到 `empty_min`（严格，可能产生伪目标）；`empty_max` 只作为建立建议，不强迫删除已有目标。`[KRD Threads]` 空层不显示标题。
- 开启“规划时强制回应”且上下文包含 `threads_requiring_response` 时，规划回合必须逐条回应目标/约定：`advance / defer / waiting / no_change`，每条一句依据；只有 `threads_reference` 时不要求回应。只要求表态，不强制推进。
- 普通聊天默认显示 `[KRD Threads]` top 5 摘要（不含档案全文）；执行上下文只显示当前小项关联的那条。
- 规划上下文默认给最近 3 天完整计划、更早 4 天摘要、最近结果、未完成和未来安排；Threads 前 5 条给档案全文，其余给摘要；历史规划回合会压缩成一行摘要，避免完整计划 JSON 反复进入会话记忆。
- 正常模型响应即 `triggered`；`<msg/>` 是合法的 `triggered_silent`，不是失败。
- `must_message` 在安静时段外单独记录 `delivery_unmet`，不把投递要求与模型成功混淆；已有项因配置变更落入安静时段时，安静优先，`<msg/>` 合法且不记 `delivery_unmet`。

### 精确、时间窗与概率

- 精确到秒；支持 IANA 时区、跨午夜与 DST 检查。
- 日历事实与日型分离；基础日型默认关闭，预设模板单独分区折叠；支持同日多个日型按优先级拼接提示词。
- 天气接入支持 WebUI 内切换 Provider 并按 Provider 保留 API Key/联系标识；保存后立即使新请求生效。
- 时间窗内随机一次，或按最小/最大间隔生成多次独立小项。
- 随机落点、概率抽签与执行认领先于外部副作用写入 SQLite；重载不重抽。
- 默认每日 **2–12 项**，bot 不必塞满。
- 禁止执行、安静投递、必需覆盖时段分别配置。
- 普通聊天可分别开关「当前生活状态」和「待办清单」，并可设置待办字符上限；设置页所有可见项都有小白说明。

### 人格与日型

- Plan、DayState、Experience、日型、会话池、天气、图片与运行记录按 `persona_id` 隔离。
- 切换人格会暂停旧生活线并恢复新人格自己的有效安排，不共享“我的昨天”。
- 工作日、周末、假日、调休工作日为内置日型；可创建大量自定义日型。
- 每个日型可覆盖规划提示词、数量、会话策略与日期规则。

### 每日总体状态

Plan 保存预计服装、心情与总体思路；DayState 保存当前服装、心情、地点、活动和思路。当前值优先，明确修改才改变，不让早晨设定绑架整天上下文。

### 梦境与安静活动

```text
凌晨 silent 做梦 → 私有 Experience → 早晨 auto/must_message 梦后分享
```

安静活动不要求发言；只有需要后续引用的体验才写记录。

### 天气与头像

无账号优先：

| Provider | 范围/说明 |
|---|---|
| Open-Meteo | 全球，非商业免费有额度并需署名 |
| MET Norway | 全球预报，需真实 User-Agent、缓存和署名 |
| US NWS | 美国境内，需 User-Agent |
| Bright Sky / DWD | 德国观测突出，预报覆盖较广 |

免费注册/免费套餐：WeatherAPI、Visual Crossing、和风天气、Weatherbit、OpenWeather。套餐与额度以服务商当前页面为准；OpenWeather 的部分产品可能需要信用卡或订阅验证。

支持真实、虚拟和混合模式；虚拟气候可复现并明确标记来源。天气失败使用新鲜缓存或带时间的旧缓存，不阻塞调度。

天气分为**当前观测**与**目标日/后续日预报**。规划/复盘使用目标日预报，目标日可分时段，后续日默认只给日摘要；普通聊天的当前天气与未来预报分开开关。日历按日期显示对应预报高低温，并支持法定假期后台自动更新与手动更新。

城市搜索：Open-Meteo 基于 GeoNames，中文城市会自动尝试“市/县”后缀并显示完整国家/省/市/区层级，重名结果可按行政层级选择；中国区县/镇级覆盖有限。选择 QWeather 并配置 Key 后走和风 GeoAPI，中国区县覆盖更完整（镇级仍取决于其地理库）。

生活头像默认按稳定顺序自动获取在线适配器头像，之后回退人格参考图和问号占位 `assets/avatar.svg`。普通读取使用 24 小时缓存；**每次重新进入前端都会后台强制刷新远程头像**，不阻塞首屏，失败继续使用最后可用图片。也可上传头像与生活横幅；图片在本机校验、重编码并去 EXIF。

### 可视化面板

- 此刻：当前状态、天气、下一项、今日时间轴。
- 小项可跳过本次、删除；时段可删除；整天计划由用户删除。删除为软删除，保留 revision；定时规划不受删除影响。
- 日历：月视图、日期详情与日型颜色。
- 变化：字段级 diff、修改原因、运行回执。
- 模板：内置/自定义计划模板均可编辑、另存与恢复默认；日型可编辑周规则、日期范围、规划/执行提示词；15 套独立角色主题、头像与横幅。
- 设置：规划、数量、三类时段、会话权限、天气、数据与诊断。
- 手机式界面：状态栏、锁屏时钟、底部应用 Dock、桌面与手机全屏自适应、15 套独立角色主题。
- 普通聊天上下文统一为 DayState + 天气 + todo agenda；日期按跨日/时区条件显示，待办项带 8 位短 ID。
- 天气块会显示配置的地点名（如桂林市），再给出当前/今日天气。
- 桌宠 23:00–06:00 才允许夜间自动睡；休息日程优先，互动会唤醒并增加之后随机入睡概率。
- 像素生活伙伴：识别日程关键词、天气、时间与事件，拥有连续跳跃、阅读、赶路、打盹、被拿起、丢起、落地等动作；会按番茄/薄荷/石榴/老板娘/天使五种口吻（第一位角色用第一人称，不自报名字）随机聊剩余事项、序号、标题、内容、时间和目标会话；陪伴模式的「聊天」「摸摸」及直接触摸也会读取真实日程再回应，关键词随主题配色高亮。天气只增加聊天，不会锁定动作。
- 完整动态默认开启，顶栏可切换全开/精简；系统“减少动画”不再静默关闭开屏和天气光效；WebSocket 增量刷新。
- 插件页 WebSocket 使用认证连接、心跳和退避重连；计划、触发和状态变化自动刷新。立即规划/立即触发有 5 秒防抖，重复点击会提示剩余秒数。
- 日历翻月缩放锚点为 `YYYY-MM`；天气预览支持虚拟/真实校验、加载提示和结果反馈。
- 所有业务配置保存即热生效，revision 冲突不会静默覆盖。

## 安装

将本仓库完整目录放到 KiraAI 的 `data/plugins/`：

```text
KiraAI/
└── data/
    └── plugins/
        └── kira_rhythm_Date/
            ├── main.py
            ├── manifest.json
            ├── schema.json
            ├── krd/
            ├── web/
            └── assets/
```

在插件管理中加载/重载 KRD，打开主 WebUI 左侧「生活节律」。首次使用建议：

1. 选择当前人格与允许会话；
2. 检查每日数量、规划时间与三类时段；
3. 按需配置天气地点或虚拟气候；
4. 点击「给予规划机会」，让 bot 创建或修订计划。

`startup_plan` 默认关闭，避免安装/凌晨启动时补跑昨日规划。需要自动启动补建时可显式开启。

## 历史与缓存

| 模式 | 行为 |
|---|---|
| `notice`（默认） | `[生活节律｜系统触发]` 短标记正常入历史；动态指令与状态全部 `persist=False` |
| `full` | 额外持久化用户明确选择的规划/执行模板，动态状态仍不持久 |
| `none` | 短标记也非持久；当前 3.1.2/3.2 的纯日程批次会留下空 user 记录，页面明确提示 |

这与主动唤醒 v2.5.0 和 QQ增强 v1.4.6 的边界一致：系统来源标记正常保存，附加动态上下文使用尾部非持久 Prompt。静态工具说明进入 `tools` system 区。

页面 HTML 和前端 API GET 请求使用 no-store；内置 CSS/JS、主题和桌宠资源带 `?v=1.3.7` 版本键；上传资源使用内容哈希和 immutable 缓存。这样既不会拿旧静态文件，也不会让动态 API 被中间缓存污染。

## 权限与安全

- 页面、API、WebSocket 均使用框架鉴权，不提供 `auth=False`。
- 会话采用白/黑名单、独立规划/执行池，执行时复核适配器权限。
- 默认空黑名单表示全允许；白名单为空表示没有可用会话。
- 天气密钥使用框架敏感字段，不进入自定义 API、WS、导出或日志。
- 上传图片限制 5 MiB、最大边 4096，服务端验证真实格式并重编码；不开放用户 SVG。
- 日程工具不能提高自身权限、修改概率下限或清除审计。

## 已知边界

- 进程在平台已发送而本地未落账的极窄窗口崩溃时，插件无法证明外部恰好一次；不确定运行标 `interrupted`，不盲目重发。
- 加速器流式抢发可能早于最终 XML 改写。KRD 用私有 Experience + 最终 `<msg/>` 和响应层抑制来避免静默泄漏；若要求对任意模型输出绝对强制静默，需要加速器提供请求级 suppress 能力。
- 天气套餐、接口覆盖和服务条款可能变化，Provider 元数据与 UI 应以官方当前页面为准。
- 导入备份在单事务中重映射对象 ID；不导入/重放 Run，历史计划归档，未决历史小项取消，已有同日计划跳过。
